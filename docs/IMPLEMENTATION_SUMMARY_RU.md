# Что готово к пилоту

Исходная ветка — `main`, коммит `90c24cf`. Тестовый интерфейс, функции и схема расширены без замены действующей Telegram-аутентификации. На PODMENA-TEST выполнена инвентаризация метаданных с доступом только на чтение. Полученные исходники `telegram-auth-` v3 и `telegram-profiles` v1 сохранены для воспроизводимости. Код `telegram-shifts` v4 до изменений совпадал с коммитом `90c24cf`. Ранние миграции добавлены в репозиторий для локального запуска полной цепочки. Записи пользователей из PODMENA-TEST не выгружались.

## A. Уведомления

Изменение смены или сообщения и запись в очередь выполняются в одной транзакции. Очередь учитывает настройку получателя и идентификатор исходного события. Поддерживаются отклик, назначение, отказ, отмена, повторное открытие поиска, запрос и подтверждение завершения, событие спора, запрос на связь и новое сообщение. При повторном открытии уведомляются только сотрудники с действующим откликом. Следующее назначение использует обычное событие назначения.

Функция `telegram-notifications` принимает служебный POST, забирает до пяти задач, отправляет короткое сообщение со ссылкой на Mini App и фиксирует результат. Тексты переписки, причины спора, суммы и контакты в уведомления не включены. Неизвестный результат отправки отмечен отдельно. Повторяется только явно подтверждённый отказ Telegram, который допускает повтор. Доставка запускается по расписанию только после разрешения владельца.

## B. Каталог и чаты

Каталог доступен руководителям. Публикация анкеты сотрудника выключена по умолчанию. Для каталога есть отдельное описание. Можно фильтровать по городу, району, площадке, опыту и формату работы. Карточка показывает только опубликованные поля и статистику подтверждённых смен. Приватные контакты остаются в своей таблице.

Руководитель отправляет запрос на связь. Сотрудник принимает, отклоняет или блокирует его. Из допустимых откликов можно открыть диалог, связанный со сменой. Сервер проверяет участника и право отправлять при каждом запросе. В «Чатах» доступны входящие запросы, непрочитанные сообщения, история, отправка, блокировка и жалоба. Обновления запрашиваются периодически во время просмотра. Жалобы сохраняются для уполномоченного владельца. Автоматических блокировок по жалобе и отдельной панели модератора в пилоте нет.

Интерфейс вызывает `telegram-social` с действующим Bearer токеном. Данные операции передаются как `{action,input}`. Postgres проверяет хеш токена и состояние связей. Подробнее о настройке и проверке в [инструкции](DEPLOY_RUNBOOK_RU.md) и [чеклисте владельца](USER_ACCEPTANCE_TEST_RU.md).

## C. Безопасность

Исправлены повторы сообщений в споре и принятие предложения из устаревшей вкладки. Безопасно отозван избыточный прямой вызов платформенной функции автоматического включения RLS. Существующий DDL-триггер продолжает работать. Новые таблицы в приватной схеме используют RLS и закрыты для прямого доступа. Проверки секретов и полномочий остаются на сервере. CI запускает локальные проверки с синтетическими данными и не развёртывает код.

## D. Интерфейс и пилот

Мобильная разметка учитывает safe area, размеры элементов и перенос длинного текста. Добавлена справка, поддержка и предварительные редакции политики конфиденциальности и правил для юридической проверки. Доступны дизайн-токены и схема событий аналитики. Для PODMENA не подтверждён настроенный проект PostHog. Аналитика выключена и сетевых вызовов не делает. Файл или макеты Figma не создавались.

Пилот сохраняет существующие смены, профили, отзывы и историю споров. Выплаты, штрафы и фактическая доставка уведомлений требуют отдельных решений и проверок владельца.
