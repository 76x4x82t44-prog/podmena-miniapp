# Проверка безопасности пилота

## Что проверено в PODMENA-TEST

22 ноября 2026 года контур проекта проверили запросами только для чтения. Проверяли определения функций, права, настройки RLS, типы объектов и рекомендации Supabase Advisor. Строки с профилями, сменами и перепиской не выгружали. Точные исходники развёрнутых `telegram-auth-` (v3) и `telegram-profiles` (v1) положили в репозиторий для воспроизводимости. У `telegram-shifts` была активна v4. Выдача Telegram-сессии и правила доступа к профилям сохранили прежний контракт.

| Наблюдение | Важность | Решение |
| --- | --- | --- |
| `PUBLIC` давал `EXECUTE` на `public.rls_auto_enable()` ролям `anon`, `authenticated` и `service_role`. Функция имеет тип `event_trigger`, PostgreSQL ограничивает обычный вызов такого объекта. | Низкая. Избыточный доступ, подтверждённого чтения данных через него нет. | `20261122095300_pilot_security.sql` отзывает прямые права только для проверенной конфигурации. Действующий DDL-триггер `ensure_rls` и владелец `postgres` сохраняются. На локальной базе тест воспроизводит отзыв и создание таблицы с автоматическим включением RLS. |
| Повтор POST ответа по спору мог сохранить его второй раз. Принятие из старой вкладки могло примениться к более позднему предложению. | Средняя. Затрагивает целостность истории спора и семантику согласия. | Ключ запроса, версия открытия спора и версия конкретного предложения проверяются в транзакции под блокировкой смены. Повторы возвращают сохранённый результат. Устаревшее предложение отклоняется. |
| У 11 приватных таблиц в `podmena` Advisor показывает включённый RLS без политик. Каталоги PostgreSQL подтвердили отсутствие `SELECT` у `anon` и `authenticated` на всех этих таблицах. | Информационная. | Прямое чтение и запись пользователями закрыты. Селективная выдача идёт из RPC после проверки сессии. Широкие политики здесь ослабили бы модель доступа. |

## Матрица прав

| Объект или действие | Кто может выполнить |
| --- | --- |
| Войти | Пользователь со свежим Telegram `initData` с корректной подписью бота. Повторная выдача сессии по тому же подписанному набору данных закрыта. |
| Вызвать SQL RPC проекта | Edge Functions с серверной ролью. `anon` и `authenticated` не могут выполнить RPC. Пользовательские операции внутри RPC сопоставляют серверный хеш с действующей Telegram-сессией. |
| Прочитать или изменить приватные контакты | Владелец контактов через профиль, от имени которого выдана сессия. |
| Назначить сотрудника, ответить на спор | Руководитель своей смены. Состояние назначения и спор проверяются под блокировкой строки. |
| Принять предложение или отозвать спор | Назначенный сотрудник своей смены. Принятие связано с показанной версией предложения. Отдельное подтверждение выполнения сохраняется. История спора приватна для участников. |
| Каталог сотрудников | Руководитель с действующей сессией. Видны только включённые пользователем данные каталога. Выдача не содержит контактов, Telegram ID и идентификатора аккаунта. |
| Запросить связь или написать | Полномочия определяет сервер. Из каталога отправляется отдельный запрос. Диалог открывается после согласия либо из допустимого взаимодействия по смене. Чтение и отправка ограничены участниками. Блокировка запрещает новые сообщения между аккаунтами. |
| Забрать задание и сохранить результат уведомления | Внутренний воркер. Отдельный секрет действует только на Edge Function обработчика. Публичный каталог, чат и спор не получают токен бота. |

## Настройки и пределы проверки

- `initData` проверяется HMAC-схемой Telegram. Допустимый возраст 5 минут, допуск часов вперёд 30 секунд. Выданный случайный Bearer действует 1 час. Сервер хранит SHA-256 токена, страница держит Bearer в памяти и сбрасывает состояние при завершении сессии.
- CORS ограничивает обращения браузеров ожидаемым origin. Допуск ко всем операциям определяется сессией и состоянием в базе. Запрос с доверенным origin без сессии отклоняется.
- Приватная схема `podmena`, явные `REVOKE`, RLS и фиксированный `search_path` у привилегированных RPC помогают ограничить доступ. Значения передаются как параметры, пользовательский текст отображается через экранирование или `textContent`.
- Политика Telegram может запретить доставку пользователю, если бот заблокирован или диалог с ботом не начат. Ошибка доставки отделена от операции приложения. Неопределённый сетевой результат отправки требует проверки журнала очереди, повторная отправка может создать дубль.
- Объекты пилота ещё не применены в PODMENA-TEST. Проверка каталога, чатов, уведомлений, миграций, реальной доставки, ротации секретов и cron в работающем проекте ожидает отдельного согласованного запуска. Автоматические тесты используют синтетические записи, временную базу и подмену сетевых сервисов.
