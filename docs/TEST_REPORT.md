# Отчёт о тестах пилота

## Воспроизводимый запуск

Из корня проекта с Node.js 24:

```bash
npm ci --prefix tests
npx --prefix tests playwright install chromium
npm test --prefix tests
```

По группам:

```bash
npm run test:sql --prefix tests
npm run test:edge --prefix tests
npm run test:browser --prefix tests
```

Для локальной проверки в Codex использованы Node.js 24, PGlite и системный Chromium. Команда для уже установленного Chromium:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium PODMENA_CHROMIUM=/usr/bin/chromium npm test --prefix tests
```

## Подтверждённые результаты

| Проверка | Результат |
| --- | --- |
| Базовая цепочка 3А–3Ж и исходный smoke-тест спора | Прошли перед внедрением пилотных изменений. |
| Миграции и SQL | 11 миграций, 4 SQL-сценария и отдельная проверка отката прошли. Проверены очередь, каталог, согласие, права, отправка, повторные запросы, блокировка, спор и повторное включение защиты после возврата к RPC 3Ж. |
| Edge Functions | 16 из 16. Проверены исходные обработчики входа и профилей, новый API чатов и воркер с локальной подменой Bot API. |
| Браузер | 2 из 2. Playwright проверил каталог, запросы, настройки, чаты, XSS, повтор отправки, блокировку, переключение вкладок, длинные строки и справку на 360, 390 и 430 px. |
| Дополнительная проверка на локальном PostgreSQL | Два соединения одновременно ожидали одну блокировку смены. Назначен один сотрудник. Повтор чата создал одно сообщение и одно задание. Воркеры получили непересекающиеся задания. |

## Найденные и исправленные ошибки

- На первом прогоне тесты очереди и версий спора падали на отсутствовавших операциях. Они прошли после реализации.
- В этапе 3Ж повторная отправка ответа и принятие устаревшего предложения нарушали целостность журнала. Регрессия покрыта SQL-проверками.
- В исходном контуре проверены рекомендации Supabase Advisor без изменения проекта. Итоги и исправление прав на `rls_auto_enable()` описаны в [проверке безопасности](SECURITY_REVIEW.md).

## Проверки после установки

Миграции пилота не применялись в PODMENA-TEST. Реальный Telegram WebView, доставка согласованным аккаунтам, настройки cron и Vault, права на установленном сервере и восстановление после отката проверяются владельцем по [чеклисту](USER_ACCEPTANCE_TEST_RU.md). В автоматических тестах использовались вымышленные аккаунты. Реальных сообщений через Bot API не отправляли.
